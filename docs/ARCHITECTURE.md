# سند جامع معماری سامانه برنامه‌ریزی تولید و کنترل موجودی قطعات فلزی خودرو (KPIMS)
**Kosar Production & Inventory Management System (KPIMS)**

---

## ۱. نمای کلی سیستم و نیازمندی‌های صنعتی
سامانه **KPIMS** یک نرم‌افزار تخصصی و تحت وب است که به منظور مدیریت جامع خطوط تولید، برنامه‌ریزی تیراژ قطعات، کنترل کار در جریان ساخت (WIP) و حسابداری مقداری انبار در کارخانه‌های تولید قطعات پرسی و بدنه فلزی خودرو (تأمین‌کننده ساپکو، ایران‌خودرو و سایپا) طراحی شده است.

### ابعاد عملیاتی کارخانه:
* **کاتالوگ قطعات فعال:** ۵۲ قطعه شامل ورق‌های روغنی/کشش عمیق (DC04, ST14, DX51D, ST37)، قطعات نیمه‌ساخته (بلنک، پوسته، براکت، دیاق) و مجموعه‌های نهایی خودرویی (پژو ۲۰۶، پژو ۲۰۷، تارا، دنا پلاس، شاهین، کوییک).
* **ماشین‌آلات و خطوط:** پرس‌های هیدرولیک کشش عمیق ۸۰۰ تن، پرس‌های مکانیکی ضربه‌ای شولر ۴۰۰ و ۲۵۰ تن، پرس برک‌های CNC ۱۶۰ تن، گیوتین و خطوط نواربری کویل ساپکو، سلول‌های رباتیک جوشکاری CO2 و دستگاه‌های پرس‌جوش مقاومتی.
* **قالب‌ها و سنبه‌ماتریس‌ها (Dies & Molds):** سنبه‌ماتریس‌های کشش، بلنکینگ، فرم، پانچ و فیکسچرهای جوش متصل به قطعات با شمارشگر ضرب (Stroke Counter) و پایش طول عمر استاندارد.
* **واحدهای سنجش موجودی:** کیلوگرم (KG) برای رول و شیت ورق ساپکو و ضایعات؛ عدد (PCS) برای قطعات کار در جریان و محصول نهایی با ضریب تبدیل وزنی استاندارد.

---

## ۲. پشته فناوری (Technology Stack)
* **Frontend:** React 19 + TypeScript با Vite و Tailwind CSS (محیط کاملاً فارسی راست‌چین RTL با فونت استاندارد Vazirmatn).
* **تقویم و زمان:** پشتیبانی بومی از تقویم خورشیدی جلالی (Jalali Solar Hijri Calendar) در تمام فرم‌ها و گزارش‌ها.
* **Backend:** Node.js + Express در بستر معماری ماژولار REST API.
* **پایگاه داده رابطه‌ای:** PostgreSQL 15+.
* **ابزار نگاشت شیء-رابطه‌ای (ORM):** Prisma ORM v6 (Type-safe با پشتیبانی از تراکنش‌های اتمیک).
* **اعتبارسنجی داده‌ها:** کتابخانه استاندارد Zod در لایه سرور جهت تضمین قراردادهای داده.
* **احراز هویت و دسترسی:** ماتریس ۵ سطحی کنترل دسترسی بر پایه نقش (RBAC) یکپارچه‌شده با Firebase Authentication.

## ۴. مدل‌های داده تعریف‌شده در Prisma Schema (`prisma/schema.prisma`)
۱. `User`: شناسه، ایمیل، نام پرسنلی، کد پرسنلی و نقش سازمانی (ADMIN, PRODUCTION_MANAGER, WAREHOUSE_KEEPER, QC_INSPECTOR, LINE_SUPERVISOR).
۲. `Part`: کاتالوگ ۵۲ قطعه، گرید متالورژی (DC04, ST14, DX51D, ST37)، ضخامت (mm)، کد ساپکو، مدل خودرو، حداقل و حداکثر موجودی.
۳. `FactoryHall`: سالن‌های کارخانه (برشکاری، پرس‌های سنگین، پرس‌های سبک، جوشکاری، رنگ کاتافورز ED، مونتاژ و انبارها).
۴. `Machine`: پرس‌های ضربه‌ای و هیدرولیک با قابلیت‌های چندگانه (`capabilities: ProcessType[]`)، ابعاد میز، کورس ضربه، سرعت SPM و اپراتور مسئول.
۵. `DieMold`: قالب‌های سنبه‌ماتریس و فیکسچرهای جوش، تناژ مجاز پرس، عمر استاندارد ضرب (Stroke Life) و وضعیت آماده‌به‌کار یا تعمیرات.
۶. `ProductionRoute` & `RouteOperation`: مسیرهای فرآیندی ساخت قطعات با ترتیب مراحل (OP10..OP80)، قالب مورد نیاز، زمان سیکل و نرم مجاز ضایعات.
۷. `InventoryTransaction`: اسناد غیرقابل‌تغییر کاردکس (رسید، حواله، تولید، ضایعات، انتقالات WIP، اسناد تعدیل) همراه با شماره یکتا و کاربر صادرکننده.
۸. `ProductionPlan`: برنامه‌های زمان‌بندی هفتگی و ماهانه، اولویت سفارش (عادی، فوری، بحرانی خط خودروساز) و نرخ تحقق تولید.
۹. `SapcoCoilReceipt`: ردیابی رول‌ها و کلاف‌های ورودی ساپکو با شماره سریال کویل، شماره ذوب (Heat No)، عرض، وزن ورودی و مانده وزنی.
۱۰. `SystemAuditLog`: ثبت رخدادهای امنیتی، اصلاحی و تغییرات پایگاه داده.

## ۵. متغیرهای محیطی مورد نیاز (.env)
برای اتصال سامانه به پایگاه داده واقعی PostgreSQL و سرویس‌ها، متغیرهای زیر در فایل `.env` یا Secrets پلتفرم مقداردهی می‌شوند:

| نام متغیر | نوع | توضیحات |
| :--- | :--- | :--- |
| `DATABASE_URL` | الزامی برای PostgreSQL | رشته اتصال کامل به دیتابیس PostgreSQL (شامل پورت ۵۴۳۲، نام کاربری و پسورد) |
| `PORT` | اختیاری (پیش‌فرض ۳۰۰۰) | پورت اجرای وب‌سرور Express |
| `NODE_ENV` | اختیاری | وضعیت اجرا (`development` یا `production`) |
| `APP_URL` | خودکار در پلتفرم | آدرس URL میزبان سامانه جهت کال‌بک‌ها و سرویس‌ها |
| `GEMINI_API_KEY` | سیستمی پلتفرم | کلید معتبر جهت ماژول‌های آتی هوش مصنوعی در پلتفرم |

نمونه مقدار `DATABASE_URL`:
```env
DATABASE_URL="postgresql://kpims_user:SecurePassword123@localhost:5432/kpims_production?schema=public"
```

## ۶. نحوه اجرای مایگریشن‌ها در پایگاه داده (Prisma Migrations)
پس از فراهم‌شدن سرور PostgreSQL و قرار دادن `DATABASE_URL` در محیط، دستورات زیر در خط فرمان پروژه اجرا می‌شوند:

### ۱. ایجاد و اعمال مایگریشن اولیه (Development Migration):
```bash
npx prisma migrate dev --name init_kpims_schema
```
این دستور شمای جداول ۱۱ گانه را خوانده، فایل SQL مایگریشن را در مسیر `prisma/migrations/` ایجاد کرده و ساختار پایگاه داده PostgreSQL را تشکیل می‌دهد.

### ۲. همگام‌سازی مستقیم بدون تولید فایل مایگریشن (Direct Push):
```bash
npx prisma db push
```
مناسب برای محیط‌های آزمایشی یا استقرار سریع.

### ۳. تولید کلاینت تایپ‌اسکریپت پریسما:
```bash
npx prisma generate
```
کلاینت تایپ‌سیف پریسما را در `node_modules/@prisma/client` بازسازی می‌کند تا کدهای TypeScript بدون هیچ خطایی اجرا شوند.

### ۴. راه‌اندازی استودیوی گرافیکی وب پریسما (Prisma Studio):
```bash
npx prisma studio
```
یک محیط مدیریتی تحت وب در پورت ۵۵۵۵ جهت مشاهده، فیلتر و ویرایش داده‌های خام جداول در اختیار تیم فنی قرار می‌دهد.

## ۷. اصول محاسباتی و تضمین یکپارچگی دفاتر کارخانه
* **محاسبه سمت سرور موجودی:** موجودی قطعات به هیچ وجه بر مبنای فیلدهای قابل ویرایش کلاینت نیست؛ بلکه سرور بر اساس گردش کاردکس اسناد قطعی (`CONFIRMED`) موجودی مرحله‌ای، موجودی قابل استفاده، قطعات در ترانزیت و ضایعات را به‌صورت قطعی محاسبه می‌کند.
* **جلوگیری از موجودی منفی:** قبل از ثبت هر حواله خروج، ضایعات یا ارسال به مرحله بعد، موجودی فیزیکی و رزرو ایستگاه بررسی شده و در صورت کسر، تراکنش بلافاصله ریجکت می‌گردد.
* **اسناد اصلاحی معکوس:** هیچ سند ثبتی از پایگاه داده حذف فیزیکی نمی‌شود؛ اصلاح اسناد تنها از طریق صدور سند اصلاحی یا معکوس (`ADJUSTMENT`) با ثبت دلیل و کاربر انجام می‌پذیرد.
